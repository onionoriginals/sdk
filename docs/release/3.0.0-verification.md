## Release review

Completed `ce-code-review` run `20260906-090911-cc7e0c5f`: ten local lenses and
an independent Claude Opus 5 adversarial pass, followed by one validator batch.
Requested peer high effort could not be verified. Follow-up inspection and
regressions close all nine findings; no new concrete regression was found.

The fixes verify reveal witnesses before either SDK or HTTP submission, replay
both evicted transactions through automatic and manual recovery, meter costly
requests and bound complete snapshots to 30 seconds/512 requests by default.
They also retain signed retitles and explicit inline media, restore the hosted
evidence type, exclude genesis aliases from Bitcoin labels and discard stale
account recovery continuations. Three actual React/Chrome regressions cover
account changes and unmount; CI skips those three when Chrome is unavailable.

SDK coverage is 88.84% functions / 88.44% lines (80% required). Auth/account and
Bitcoin-spending changes remain material review surfaces even with passing
fixtures. Already initiated publication requests can finish after account change;
subsequent account writes and retained-artifact removal are guarded.

[Original review](evidence/release-review.json) and
[closure receipt](evidence/release-review-closure.json) preserve the findings.

## Existing follow-up triage

Recovery starvation and swallowed store writes were reproduced and fixed through
public poll/background seams. Five lookup slots reserve progress for every
nonempty category; store failures produce a named 503 and money log, and replay
attempts are persisted before sending. The four signer redirection/input attacks
also run in the SDK security suite.

The remaining structural-debt suggestions (extract component functions, split the
route factory, split identity UI modes, unify historical auth error shapes) do
not demonstrate an unresolved failure in this journey. They are deferred; this
release does not promise those refactors. Current named auth failures and custody
regressions remain tested.
