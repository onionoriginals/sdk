## Pre-publication automation correction

A subsequent workflow audit found that `release.yml` selected Changesets action
v2 while retaining v1 input names and the old `hasChangesets` step output. The
upstream v2 contract uses `version-script`, `publish-script`, `github-token` and
`has-changesets`. An empty job output could skip the registry/publish stages;
the old publish input would also leave the publish command unconfigured.

This correction wires the v2 contract explicitly and selects Node 24 for release
tooling while preserving the Node 20.10 consumer import gate. Four offline
workflow tests reproduce the API/runtime mismatches before the fix and pass
afterward; CI now runs them. This is workflow verification, not a live npm
publication or validation of the stored npm token. The runtime/mainnet evidence
above remains valid; include this correction before the stable Version Packages
merge.

`NPM_TOKEN_EXPIRES_AT` was absent from repository variables at this audit. The
secret was last updated on 2026-07-27, but GitHub metadata cannot establish its
chosen expiry or current write permission. Follow the existing token runbook;
the publish workflow retains its authenticated no-write preflight.
