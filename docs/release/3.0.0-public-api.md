# SDK 3.0.0 public API freeze

Every symbol marked **keep** below is supported within its documented purpose and
semantic-version contract. A future major release may change that contract. No
exported SDK API is marked experimental. Only the package exports map and CLI
are supported entry points; deep files included in `dist/` remain implementation
details. The unexported migration engine is experimental.

## Decisions and scope

- Root/default `OriginalsSDK`, `OriginalsAsset`, `LifecycleManager`, their config/resource/result types, and `/types` describe CEL 3. The `/v3` SDK is local-only. `/cel` re-exports the selected `@originals/cel/v3` core.
- The separate CEL package root retains previous-format APIs used by internal consumers; its `/v3` entry is the selected asset profile. This is not an old-format fallback in the SDK lifecycle.
- Independent identity, credential, resource, Bitcoin, provider, signer, storage, network preset, metrics and event utilities remain supported as-is. Credential derivation and automatic asset migration credentials remain deferred; BBS+ selective disclosure (`bbs-2023`) is parked and fails closed (#591). Kind/manifest validation is a utility, not authenticated asset metadata.
- Network preset/domain/context helpers remain configuration utilities. Their values do not attest a deployed service or select a publishing host. Every WebVH writer requires an explicit host.
- `OriginalsSigner` and `ExternalSigner` remain identity/credential utilities. CEL 3 asset custody uses `CelSigner` without implicit conversion. `MockRemoteSigner` remains a signer-conformance fixture; provider doubles stay on `/testing`.
- `EventEmitter` and `EventLogger` retain the independent typed event vocabulary. CEL 3 lifecycle methods return explicit results and do not emit the previous implementation's asset payloads. Those payload declarations remain internal to the utility graph. The retained `MigrationError` type does not expose the experimental migration engine.

## CLI contract

`originals-cel` supports local `create`, `verify`, `inspect`, `--help`/`-h`,
and `--version`/`-v`. Creation requires `--file`, `--media-type`, `--algorithm`,
and `--key`; `--name` and `--output` are optional. It emits a version-3 envelope
and refuses to overwrite an existing output. Algorithms are Ed25519, P-256 and
P-384, with raw binary private-key files sized for the selected algorithm.

`verify --asset` checks full local history and bytes. `inspect --asset` can
report authenticated partial material. `verify --log` and `inspect --log` accept
`--format json|cbor`; history-only verification does not establish resource or
publication evidence. A successful history check exits zero; errors exit nonzero.
There are no network publishing or resolver commands. The option names, artifact
shapes, and documented verification scopes are supported; terminal presentation
is not a machine API. See [V3.md](../../packages/sdk/V3.md) for examples.
