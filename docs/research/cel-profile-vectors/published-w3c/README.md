# Published W3C cryptographic vectors

The three JSON files contain **literal example text from fixed W3C Recommendations dated 15 May 2025**. Each example retains its number and direct source URL. Published keys are public test fixtures. No expected canonical output, hash, key, or signature was generated by Originals code.

| File | Published examples |
| --- | --- |
| `ecdsa-jcs-2019-p256.json` | ECDSA Appendix A.5, examples 49–59 |
| `ecdsa-jcs-2019-p384.json` | ECDSA Appendix A.6, examples 60–70 |
| `eddsa-jcs-2022-ed25519.json` | EdDSA Appendix B.3, examples 29–39 |

Run from the repository root after its frozen Bun dependency installation:

```sh
bun docs/research/cel-profile-vectors/published-w3c/compare.mjs
```

The script uses installed `@noble/curves` and independent `json-canonicalize` 2.0.0, with Node crypto for hashes. It imports no Originals implementation and does not access the network. Its canonicalizer path explicitly follows this repository's Bun dependency layout. `validation.json` records the successful run and actual versions.

The comparison checks every published canonical string and intermediate hash, signature encoding, assembled document, signature verification, and deterministic signature generation. It also demonstrates that these ECDSA vectors require hashing the concatenated hashes as an ECDSA message, and that the published P-384 signature is valid with high S.

**Coverage is cryptographic vector behavior only.** This does not test complete Data Integrity processing, controller authorization, context/purpose validation, CEL parsing/folding, or Originals protocol conformance. Arbitrary valid randomized ECDSA signatures need not match the deterministic published signature bytes.

To re-extract the literal evidence from those two fixed official pages:

```sh
python3 docs/research/cel-profile-vectors/published-w3c/extract-published.py
```

Extraction decodes HTML character references and trims presentation whitespace outside each preformatted example. It computes only a provenance hash of the downloaded HTML; it does not regenerate any expected vector values. This optional extraction command reads the public W3C pages and rewrites these evidence files.
