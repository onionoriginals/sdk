# Worked authority histories

These are decision examples for the [authority and publication-ordering contract](../../../specs/originals-cel-v3-authority.md).
They are **not real Bitcoin observations or evidence that the new SDK works**.
The owner selected current-controller authority: rotation A → B retires A for
future entries; prior A signatures retain their historical meaning.

Start with the [plain-language walkthrough](walkthrough.md). The saved corpus
contains 24 signed entries and 42 worked histories; all 42 also pass with the
provider return order reversed. These are reference-model checks only.

`histories.json` holds actual signed entries generated from public test keys,
their independent event digests, and hand-worked expected state for each story.
Block positions, ownership, completeness and tips are explicitly declared
scenario inputs. The WebVH alias is symbolic; no SCID or live hosting is checked.

The cases cover sale, a recipient attempting to author, cooperative publication
of creator-authorized bytes, reacquisition after rotation, outgoing-key rotation
authorization, immediate B authority inside a batch, rollback of an invalid
batch, strict block-height gating, numeric same-block ordering, ignored unrelated
bytes/forks, resource continuity, terminal deactivation, explicit reauthorization,
incomplete evidence, unavailable verification capability, stable snapshots,
duplicate/conflicting records, requested identity after earliest-boundary
selection, and reorganization.

Run the saved scenarios without regenerating expectations:

```sh
node docs/research/cel-authority-vectors/check-histories.mjs
```

Generation is a separate deliberate action after a contract change:

```sh
node docs/research/cel-authority-vectors/generate-histories.mjs
```

The reference evaluation imports no Originals production code. It uses the
previously checked JCS/cryptographic reference tools; Node/OpenSSL verifies every
signature, including entries rejected later for authority/state reasons. Expected
heads/controllers/resource versions are declared directly from the contract,
not generated by the evaluator. Each story is also evaluated with reversed
provider return order against the same expected outcome.

The small evaluator assumes the declared observation quality; it does not prove
the observations, implement a production provider, validate WebVH method binding,
implement all parser/error/limit branches, or replace the required public verifier
and real regtest tests. No package imports or exports these reference scripts.
